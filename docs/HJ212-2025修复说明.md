# HJ212 协议库修复说明

日期：2026-11-15

## 本次范围

修复现有编解码库及接收示例中已确认的问题，补充不依赖真实数采仪的自动化回归测试。本项目约定的 HJ 212—2025 编解码适配、字段校验细节、附录 C 全部命令样例回归和接口一致性工作已经完成。完成范围以编解码库为限，不包含标准中的应用业务流程，也不代表全面合规认证。

依据：[生态环境部 HJ 212—2025 正式文本](https://www.mee.gov.cn/ywgz/fgbz/bz/bzwb/jcffbz/202507/W020250711505311328432.pdf)。核对第 6.3/6.4 节、表 2 至表 5、附录 A.1/A.2、附录 B 的相关类型及附录 C.1～C.63 全部命令样例。

## 修复内容

| 问题 | 修复及验证 |
|---|---|
| 新增的八处 FieldN 注解缺少必填 value，导致编译失败 | 为不规定具体宽度的数值字段配置数值校验，保留标准未限定的精度 |
| 主要解析路径只识别 2005、2017 分组 | 按完整版本位识别 2005、2017、2025；拒绝未知版本及越界 Flag |
| 深层 Map 的版本选择颠倒，MN 约束固定为旧版 | 统一版本选择，分组配置 MN 的最大长度 |
| CRC 不足四位时输出失败 | 固定四位大写十六进制；保持附录 A.1 算法，使用固定样例 2200 验证 |
| 多个因子子字段生成时错误累积路径 | 每次切换子字段替换上一个子键，保留因子前缀 |
| 2005 版 Flag=0 生成时留下空列表 | 空版本位列表生成数值 0；位合并使用按位或 |
| RF、PNUM、PNO 等数值字段无法生成或被忽略 | 序列化器支持数值标量，测试往返后保持字段值 |
| 长字段名、超过 50 字符的普通值解析失败 | 按数据段最大规模提供缓冲；测试 CompleteTime、关联信息及中文长值 |
| Java 17 无法反射读取 PushbackReader 私有字段 | 移除反射，保持共享回退流，避免临时包装造成字符丢失 |
| Reader 一次读取可能不足目标长度 | 循环读取；测试每次仅返回一个字符的输入流 |
| 字节流依赖系统默认字符集 | 明确使用 UTF-8，并按传输字节数生成长度和计算 CRC |
| 不同 Mapper 共享可变编解码器 | 工厂复制时创建独立编解码器；同步单个 Mapper 的读取和写入入口 |
| 数值下限为 0 时校验无效 | 正确执行零下限；为相关 2025 枚举字段补充非负约束 |
| 正则字段校验只检查第一个匹配项 | 遍历全部匹配项；测试后续设备的非法运行时间也能被拒绝 |
| 嵌套因子和设备未级联校验 | 补充级联标记，修复日期校验器声明及数值校验器类型 |
| 仅声明 Validation API，没有实现 | 增加 Jakarta Validation 实现与 EL；避免 Spring Boot 2 BOM 将其降级成 javax 版本 |
| 示例 Mapper 扫描包错误 | 扫描实际业务 Mapper 包 |
| Netty 拆帧移除 CRLF，后续解析却仍要求包尾 | 实际接收管道保留包尾；用半包和粘包测试验证 |
| 示例固定回复 2017 版且系统编码沿用上传值 | 回复保留原版本位，清除应答和分包位，使用 ST=91 |
| 统计报文、空 CP 或无 Rtd 时空指针 | 跳过无实时值的因子，保持示例仅存实时值的业务范围，不将 Avg 冒充 Rtd |
| 接收示例默认不检查 CRC | 在接收服务显式启用 CRC 检查，错误 CRC 不写入因子数据 |
| 启动端口绑定失败后吞异常 | 向启动调用方传播异常 |

## 后续完成的库内完善

| 内容 | 最终实现 |
|---|---|
| SM4 | 显式传入 16 字节密钥的二进制加解密，校验固定密文向量；不保存或轮换密钥 |
| 分帧 | 按声明长度读取原始字节帧，不用换行切分密文 |
| 模型 | 支持字符型 Rtd、关联 SampleType、CP 扩展字段；缺失 RS 不再自动输出 0 |
| 字面约束 | 前导零计入 N 型宽度；检查小数精度、取值及长度/CRC 字符集 |
| 日志 | 按 // 引用保留中文、空格及分隔符，检查闭合与字节长度 |
| 扁平 Map | CP 文本输出恢复 && 边界，与深层 Map 及 Data 的字段结果一致 |
| 标准回归 | 63 张表、188 条正文、69 组字段规则；记录 23 条省略样例的规范化及拒绝反例 |

## Flag 说明

正式文本表 3 对 A、D 的文字解释与同表 Flag=9 的示例存在不一致。本次遵循数值示例及附录 C 的报文行为，并保留现有库的位定义：最低位 1 为需要应答，次低位 2 为分包，2017 版本位为 4，2025 版本位为 8。没有直接交换枚举 A、D 的含义。

## 自动化验证

在项目根目录执行：

~~~powershell
mvn test
~~~

构建环境：Windows、Temurin OpenJDK 17、Maven 3.10.0；源码和目标仍设置为 Java 8。未验证 Java 8 实机运行。

当前共 3368 项测试全部通过，失败、错误、跳过均为 0；核心模块 3365 项，示例模块 3 项。详细分项、样例出处和处理原则见 [回归覆盖说明](HJ212-2025回归覆盖说明.md)。

Netty 测试使用 EmbeddedChannel 和数据库 Mapper 替身，调用实际接收服务及管道；不连接现场设备、真实 TCP 网络或真实数据库。故不能将其等同于设备联调、数据库集成测试或生产压力测试。

截至本轮完善，已实现 SM4 字节加解密、字符型 Rtd、扩展字段保留、二进制长度分帧与显式严格校验。完整 API、校验清单和测试范围见 [2025 编解码使用说明](HJ212-2025编解码使用说明.md)。

数据库、密钥生命周期、重发调度、会话缓存及设备控制不属于编解码库职责，不再作为本项目必须补齐的能力。示例模块本轮没有扩展业务。真实设备互操作和 Java 8 运行环境尚未验证。
