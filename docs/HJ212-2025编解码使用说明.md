# HJ 212—2025 编解码使用说明

## 当前状态

本项目约定的 HJ 212—2025 编解码适配、字段校验细节、附录 C 全部命令样例和接口一致性回归已完成。当前定位为支持 HJ 212—2025 的编解码库，验证范围与逐项结果见 [回归覆盖说明](HJ212-2025回归覆盖说明.md)。

## 库的职责

核心模块 protocol 提供污染物自动监测报文与 Java 模型之间的转换，以及对应的语法、字段校验和显式加解密。它不连接数据库，不发起网络连接，不分配设备身份，不存储或轮换密钥，不执行重发、补传、设备控制和定时任务。

分包的 PNUM、PNO、补传标志 RF 可以编解码及校验；跨连接缓存、包重组策略、超时重发属于调用方的会话管理。本库不把这些应用功能列为待实现缺陷。

## 明文接口与严格模式

~~~java
ProtocolMapper mapper = new ProtocolMapper().enableStrict2025();
Data data = mapper.readData(packetBytes);
byte[] output = mapper.writeDataAsBytes(data);
Map<String, Object> raw = mapper.readDeepMap(packetBytes);
byte[] rawOutput = mapper.writeMapAsBytes(raw);
~~~

保留 String、byte[]、Reader、InputStream 解析入口，以及 String、char[]、byte[]、Writer、OutputStream 输出入口。建议使用字节接口传输 UTF-8 报文。

默认开关保持旧调用兼容。enableStrict2025() 显式组合默认字段校验、包头、包尾、长度、CRC 与 STRICT_2025。已识别为 2025 版的报文会接受更严格校验；2005/2017 继续使用原有版本分组。没有 Flag 的旧式报文不推断成 2025。单独启用 STRICT_2025 仅开启严格字段语法检查；需要完整组合时使用 enableStrict2025()。

配置完成后可复用 Mapper。同一个 Mapper 的读写入口进行同步，不同 Mapper 使用独立的编解码器实例。运行中不应并发修改配置；这不等于无锁并行处理。

### 严格校验范围

- 必要头字段、QN 时间戳、ST/CN 格式与命令范围、PW 字符集、MN 的 24 位大写十六进制编码；附录 C.2 首次联网 CN=1001 及 CN=9013 通知应答允许空 MN。
- Flag 的完整版本位；分包时需要 PNUM/PNO 且包号不超过总包数，非分包不得携带包号；RF 存在时必须为 1。
- CP 长度包含 CP=&& 与闭合 &&；严格模式限 950 个传输字节；整个数据段最大 1024 字节。
- 日期与时间字段；实时上传间隔 1～3600；分钟间隔集合；超时、重发次数、瓶号、出样时长；校准及采样类型；QnRtn/ExeRtn 代码集合。
- N 型字段按原始文本检查整数位数（含前导零）和小数位数；仅在检查通过后转换为数值。
- 日志字段须使用 // 包围，引用内的中文、空格、分号、逗号、等号和 && 保持原值，日志传输值须小于 890 字节。
- 数据标记长度与字符集、设备 RS/RT、标准样品浓度和实测值精度、校准结果、噪声数据精度。
- 已知数值监测字段不能误填字符；附录 B 中字符型工况和用电事件的 Rtd 允许字符串。
- 重复字段、缺等号、空项目、非法字段名、开始时间晚于结束时间。

明确命令参数必填覆盖：1000、1012、1014、1062、1064、1072、2081、9011、9012。对同一 CN 同时表示请求和上传、需要通信方向或会话上下文才能判断的情况，库不猜测其条件必填；调用方按实际方向处理。未知命令预留范围和可扩充字段不使用封闭白名单。

严格校验在 Data、Map、深层 Map、Pack 解析和输出入口共用，避免只在解码时校验。严格模式不会默认触发加密，也不会选择设备密钥。

## SM4 报文加解密

~~~java
// deviceKey 由调用方提供，长度必须为 16 字节。
byte[] ciphertext = mapper.writeDataAsEncryptedBytes(data, deviceKey);
Data decoded = mapper.readEncryptedData(ciphertext, deviceKey);

byte[] rawCiphertext = mapper.writeMapAsEncryptedBytes(raw, deviceKey);
Map<String, Object> decodedMap = mapper.readEncryptedDeepMap(rawCiphertext, deviceKey);
~~~

需要独立处理原始帧时使用：

~~~java
byte[] ciphertext = ProtocolCrypto.encrypt(plaintextPacket, deviceKey);
byte[] plaintext = ProtocolCrypto.decrypt(ciphertext, deviceKey);
~~~

实现遵循标准附录 A.2：先计算明文 CRC 并组包，之后仅对 CP=&& 与闭合 && 之间的完整 16 字节分组进行 SM4/ECB/NoPadding 转换。不足 16 字节的余段按标准保持明文；没有任何完整分组时该 CP 不产生密文字节。包头、长度、头字段、CP 边界、CRC 和包尾保持不变。解密后检查明文 CRC；密钥错误或数据损坏导致校验失败时抛异常。

本库使用 Bouncy Castle 的 SM4 实现，没有自行编写密码算法，也不修改 JVM 的全局 Provider。每次调用显式接收密钥，不在 Mapper 或全局变量中保存设备密钥，不负责密钥来源、注册、持久化、有效期或轮换。NewSK、SKCreateTime 的编解码属于库内能力，密钥管理流程属于应用层。

密文可能包含任意字节，包括零字节、换行和非法 UTF-8 序列。禁止将密文通过 new String(..., UTF_8) 转换或按 CRLF 拆帧；附录中的十六进制列表只是展示，不是传输时自动转十六进制文本。

## 二进制分帧

~~~java
// 只读一帧，正常 EOF 返回 null；残缺帧抛 EOFException；不会关闭 input。
byte[] frame = ProtocolFrame.read(input);
if (frame != null) {
    Data decoded = mapper.readEncryptedData(frame, deviceKey);
}

// 等价的便捷接口，同样只消费一帧，不关闭 input。
Data decoded = mapper.readEncryptedData(input, deviceKey);
~~~

ProtocolFrame 按固定 6 字节前缀及声明长度读取，支持短读取、连续帧和正文中的二进制换行。它只负责帧边界，不负责缓存连接、寻找丢失帧头、CRC 或设备鉴权。CRC 在明文解析或解密阶段按相应配置检查。

## 字符型监测值和扩充字段

~~~java
Pollution status = data.getCp().getPollution().get("p99101");
String text = status.getRtdText(); // 如 St
status.setRtdText("N");

Pollution numeric = data.getCp().getPollution().get("a21026");
BigDecimal value = numeric.getRtd(); // 旧的数值 API 不变
~~~

getRtd() 对字符型值返回 null，不能用它判断该监测值不存在；通用调用使用 getRtdText()。数字文本如 1.250 保留其数值精度与文本；显式 setRtd(BigDecimal) 会替换原始字符值。

未知普通 CP 字段保留在 CpData.getExtensions()，未知因子子字段保留在 Pollution.getFieldInfo()；这两类字段在模型往返时继续输出。扩展键不应与已知属性重名。报文头按标准顺序输出，CP 固定在最后；Map 插入顺序不会导致 CP 后面错误输出分包参数。首次联网的空 MN 保留为空字符串。

## 扁平 Map 与缺失设备状态

`readMap()` 的 CP 是不含外围 && 的文本，`readDeepMap()` 的 CP 是嵌套 Map；两者都可直接交给 `writeMapAsString()` / `writeMapAsBytes()`，编码器按类型恢复边界。字面格式和字段顺序可能规范化，字段语义保持一致；需要保留原始正文时使用 Pack。

只包含 RT 的设备报文不会凭空增加 RS。`Device.hasRs()` 或 `getRsValue()` 可区分未提供状态与明确 RS=0；旧 `getRs()` 仍返回 int，状态缺失时返回 0，旧 `setRs(int)` 保留。
